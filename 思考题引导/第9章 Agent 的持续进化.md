### 思考题 1 ★★

> 一条经验文档由三次成功轨迹和一次失败轨迹支持。失败发生在较新的 API 版本上。系统应如何判断这是经验被推翻，还是适用条件发生了变化？

**提示思路**：

- **第一层｜把两种假设写成可区分的预测**。「经验被推翻」断言经验本身错了；「适用条件变化」断言经验在旧条件下仍成立。分别想清楚：如果前者为真，应该观察到什么？如果后者为真，又该观察到什么？先把两者的判据写下来，再去看数据。
- **第二层｜回到载体本身**。本章 §将经验沉淀为知识 给「正式文档」列了一组应当写清的字段（适用场景、推荐策略、禁止做法、例外条件、证据来源、最近验证时间）。先问：现有这条文档里，哪些字段**本来就该承载这个判断**，而现在缺了或没更新？
- **第三层｜证据表怎么填**。同一节给出的提炼管道要求为每条经验草案建立「哪些轨迹支持、哪些轨迹反驳」的证据表。注意本体的样本结构是 3 支持 + 1 反驳——先想清楚这个比例本身能支持多强的结论，以及还需要补什么证据（例如失败的 API 版本上是否有别的成功样例）。
- **第四层｜两种结论的动作不同**。改写、加条件、拆分、标记过期——分别对应哪一类判断？本章 §睡眠学习 的第五步给了哪一种处置的完整形态？本章 §可验证闭环的边界 也提醒过：失败与阴性结果要保留，否则会反复探索已经证伪的路径。

**相关小节**：§将经验沉淀为知识（三层数据、知识提炼五步、证据表）；§睡眠学习：整合、遗忘与能力保鲜（修剪与索引）；§可验证闭环的边界：当“完成”不等于“进步”（保留负面结果）。

### 思考题 2 ★★

> 客服 Agent 的用户满意度上升，但规则违规率也上升。为什么不能把满意度作为单一学习信号？你会怎样设计护栏指标？

**提示思路**：

- **第一层｜先把两个指标放回三层结构**。回到 §从运行轨迹中获得学习信号：满意度属于哪一层验证器的输出？规则违规率属于哪一层？原文在解释中间层为什么必要时，举了两个「结果看起来没问题、过程其实违规」的例子——找出它们，看是否与本体的反向移动同构。
- **第二层｜为什么它们会反向移动**。考虑 Agent 可以通过什么路径同时抬高满意度与违规率（原文 §从运行轨迹中获得学习信号 与 §将经验写成指令 各自给了一条线索）。再考虑一个更隐蔽的原因：本章 §将经验写成指令 提到过一个与「模型把观察到的行为当应然」有关的机制——它对「用单一信号驱动更新」意味着什么？
- **第三层｜护栏指标要满足什么性质**。逐条想清楚：是否需要一个一票否决项？是否必须来自**独立于被优化目标**的证据源？是否要能在提案阶段就被检查，而不是事后才发现？本章 §从运行轨迹中获得学习信号 对验证器的输出形态给出了四项要求，其中哪一项直接对应「不许只看总分」？
- **第四层｜谁有权改护栏**。护栏指标一旦成为被优化目标就会失效——这一点与本章 §持续进化的安全边界 的第三道直接相关，也是思考题 4 的入口。

**相关小节**：§从运行轨迹中获得学习信号（三层验证、表9-1 七维度、验证器输出四项内容）；§将经验写成指令（模型把观察到的行为当作应然的行为）；§持续进化的安全边界（安全机制不可自我修改）。

### 思考题 3 ★★★

> 同一个“虚假承诺”问题可以通过 Prompt、Harness 检查或参数训练缓解。你会依据哪些证据选择修改位置？

**提示思路**：

- **第一层｜先看缺陷的表示性质**。回到 §Agent 持续进化的四种方法 与表9-2：四个载体各自的「适合承载」写的是什么？把「虚假承诺」这件事翻译成一句能力描述，再判断它更像哪一类——是能用语言清楚说明的判断原则，还是可以确定性解析的约束，还是高维隐式习惯？
- **第二层｜什么证据能证明「可以用语言说清」**。本章 §将经验写成程序 给了一条判据式的话（关于「能够确定性执行的约束」应该去哪里）。反过来想：什么样的证据会证明它**说不清**、必须内化？把两类证据都列出来。
- **第三层｜比较三种方案的成本结构**。表9-2 的「主要局限」一列分别写了什么？再叠加本章反复出现的发布门槛（§将经验写成指令 的边界集 + 保留集、§将经验写成程序 的失败轨迹重放与旧任务回归）——三种方案的验证与回滚成本各是多少？原文对「默认选择」有一句明确的建议，找出来。
- **第四层｜先排除组合之外的选项**。§Agent 持续进化的四种方法 举过医疗影像 Agent 的例子，说明同一能力可以拆到多个载体。想清楚：拆分点应该按什么划（是「能不能被符号表达完整」吗）？拆完之后每个部分的**验证责任**分别落在谁身上？

**相关小节**：§Agent 持续进化的四种方法（表9-2 适用边界、「同一能力可以拆到多个载体」）；§将经验写成指令（最小 diff + 边界集/保留集）；§将经验写成程序（结论句「能够确定性执行的约束应该进入程序」）；§将经验写入参数（表示性质决定载体）。

### 思考题 4 ★★★

> Agent 能修改工具和验证器，却不应修改批准自身更新的可信根。你会如何划分这两部分的权限和代码边界？

**提示思路**：

- **第一层｜先枚举**。本章 §持续进化的安全边界 第三道把「不能自我修改」的对象列成了一串。先把它们逐个写出来，再补上你们系统里等价的对象——「批准自身更新的可信根」在你们的部署形态里究竟是哪几个文件、哪张表、哪个服务。
- **第二层｜权限边界与代码边界是两件事**。前者是「谁能提交、谁能批准、谁能回滚」，后者是「哪些代码可以被提案触及」。本章的实验类小节里有一个权限划法的实例（关于提案方无权修改什么），把它找出来作为参照。再想清楚两者的关系：只有权限划分而没有代码隔离，会留下什么缺口？
- **第三层｜给出一条可复用的原理**。本章 §持续进化的安全边界 里有一句话，把这个要求抽象成了与第一章三层护栏呼应的一般原理。找出它，然后回答：它在你们的实际部署里对应哪个具体机制（代码所有权、仓库保护规则、独立进程、独立账号……）？
- **第四层｜处理一个真实张力**。§案例：DeepSeek Harness 以“一切皆插件”实现自我进化 明确提出「不存在一个只能由人类维护的特权内核」。如果所有组件都可装卸，可信根放在哪里、由谁维护？本章对可组合性的能力边界也有一句限定（它解决了什么、没有解决什么），用它来化解这个张力。

**相关小节**：§持续进化的安全边界（三道边界，尤其第三道）；§将经验写成程序（变更契约、隔离更新分支与发布门槛）；实验 9-7（生成提案的 Agent 无权修改安全测试和批准规则）；§案例：DeepSeek Harness（时间/空间可组合性、「不存在一个只能由人类维护的特权内核」）；实验 9-8（稳定版本、验收测试和批准门槛位于修改权限之外）。

### 思考题 5 ★★

> 经验知识库不断增长后，检索错误和知识冲突会抵消学习收益。如何设计版本、时效和淘汰机制？

**提示思路**：

- **第一层｜先把三种失效分开**。检索错误、知识冲突、内容过时是三种不同的问题，对应三种不同的机制。本章 §睡眠学习：整合、遗忘与能力保鲜 的末尾列出了一组周期性离线整理动作，以及 §将经验沉淀为知识 提到的「更长时间尺度上重现」的现象——从中挑出与三种失效各自对应的条目。
- **第二层｜三个机制各自要解决什么**。**版本**要保证可回滚、可归因、可比较——本章哪些原则要求了这三点？**时效**要回答「什么时候从『有效』变成『待复核』」——原文给文档列了一个与时间直接相关的字段，找出它。**淘汰**要回答「删掉之后如何恢复」——原文在处置长期不用的能力时，给的其实不是「删除」，找出它的实际措辞。
- **第三层｜淘汰的代价与反例**。本章 §可验证闭环的边界 给了一条与「只保留高分方案」相关的纪律，它直接约束淘汰规则该怎么写。先找出它，再想想：如果淘汰规则只看检索命中率或得分，会主动消灭什么？
- **第四层｜什么时候该重建而不是继续修剪**。§睡眠学习 的整理清单里有一条比「删除知识」更重的动作。什么条件下它比继续修剪更划算？这和 §将经验写入参数 关于「更新频率与成本」的论述怎么衔接？

**相关小节**：§将经验沉淀为知识（三层数据、五步提炼管道、证据表）；§睡眠学习：整合、遗忘与能力保鲜（五步周期、修剪与索引、周期性离线整理清单、上下文腐化）；§可验证闭环的边界（维护搜索多样性）；§将经验写入参数（稳定性影响更新频率与成本）。

### 思考题 6 ★★★

> 参数学习擅长自然语言风格，却难以保证硬性业务规则。请为医疗客服设计一套参数、知识、Skill 和代码约束协同的持续进化方案。

**提示思路**：

- **第一层｜先把能力拆到四个载体上**。回到表9-2 的「适合承载」一列，逐条对齐医疗客服的具体能力：自然的语气与共情、最新的诊疗指南与机构事实、需要权衡例外与优先级的判断原则、不可绕过的合规与隐私红线。想清楚每一条为什么落在那个载体——注意 §将经验写入参数 的口径：真正决定载体的是能力的**表示性质**，「是否长期稳定」只影响更新频率与成本。
- **第二层｜把局限写进方案**。表9-2 每一行都有一栏「主要局限」。方案里如果只写各载体的优点，等于没有设计。逐条问：这条局限在医疗场景下会以什么形式出现？哪一条最致命（提示：考虑「模型正确应用」这件事在最坏情况下意味着什么）？
- **第三层｜串成一条流水线**。把四个载体放进 §构建可长期运行的持续进化闭环 的双循环里：触发、诊断、提案、验证、发布、修剪各由谁负责？哪一步必须有人类？本章 §睡眠学习 的五步周期可以直接作为骨架，但要想清楚医疗场景下哪一步的门槛必须提高，以及 §可验证闭环的边界 提出的「让人类在更高层介入」在这里具体指什么。
- **第四层｜对准代价不对称**。医疗场景里一次违规的代价远高于一次回答不够流畅。本章有哪几条纪律恰好是为这种不对称设计的？至少用到三条，并说明各自拦截的是哪一类失败：一条讲不可信输入如何被固化成长期能力（§持续进化的安全边界 第一道）、一条讲谁能改什么（第三道）、一条讲证据如何与结论分离（§可验证闭环的边界）。最后回答本题的核心问句：为什么参数层最难保证硬规则——用表9-2 该行的措辞来回答。
