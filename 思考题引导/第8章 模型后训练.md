### 思考题 1 ★★

> **原题**
>
> ★★ 灾难性遗忘——一次针对特定任务的微调破坏了模型原有的通用能力（如通用工具调用）——在 Agent 场景下尤其棘手。相比全参微调，LoRA 冻结基座权重、遗忘风险更低，但并非免疫。有哪些策略可以进一步缓解微调带来的能力遗忘？

**提示思路**：

- **先把「遗忘」变成可测量的量。** 没有训练前的快照，就无法归因任何退化——所以你需要的第一个东西不是方法，而是一份**保留集清单**（通用工具调用、指令遵循、语言能力各留多少条？）。本章反复出现的口径是「独立保留集 + 早停」，它先于任何缓解手段。
- **把缓解手段按层归类**，再逐层检查你有没有实际用上：**参数层**（冻结基座、低秩补丁、正则约束）、**数据层**（与通用数据混合的配比、回放、难度课程）、**流程层**（阶段门禁、早停、回滚）。三层里哪一层的成本最低、收益最直接？
- **数据层的现成配方有两个，但都不该照抄**。实验 8-5 用「约 80% 韩语 + 20% 英语」抗遗忘，原书明确声明「这只是该实验的选择，不是通用默认值」；实验 8-17 用「小配比混入通用任务数据」并额外防住了把「逢收尾必验证」学成新过拟合。请自己回答：**这两个配比在解决同一件事吗？**
- **区分「遗忘」与「覆盖」。** 被覆盖的能力可能仍然存在于某个可寻址的参数子空间里。想一想：可插拔适配器（多适配器服务）相比单套权重，改变了这个问题的性质吗？
- **本章给出的一个非显性的缓解手段是「选择正确的阶段」。** 若你怀疑目标能力其实缺的是底座，那么在 SFT 上反复加数据只会一边加深遗忘、一边补不上缺口。回头查一下：你的失败到底是「会做但不按要求做」还是「根本不会做」？
- **别把 LoRA 当成免死金牌。** 题干已经点明「并非免疫」。请在自答里写下：你打算用什么**具体指标**证明这次微调没有损害通用能力？

### 思考题 2 ★★

> **原题**
>
> ★★ 后训练将能力固化为模型权重（“肌肉记忆”），而上下文学习将知识放在推理时的输入中。但有些能力（如领域知识）既可以通过后训练学习，也可以通过 few-shot 示例提供。你会用什么标准来决定某项能力应该走哪条路径？

**提示思路**：

- **本章给出的判据不是「任务是否长期稳定」。** 原书在收尾处把判据说得很直接：「选择依据不只是任务是否长期稳定，更重要的是**能力能否被外部符号充分表达**。」请先用这句话检验你的第一直觉——它会把「医疗影像识别」「自然语气」这类看似领域多变的能力推向参数侧。
- **把「能力」拆成可判定的属性清单**，逐条打分而不是笼统判断：更新频率、是否需要引用与出处、是否需要权限控制与删除、延迟与费用敏感度、确定性要求、是否需要感知（图像/语音/语气）。本章明确把前四条归给 RAG——「需要动态更新、引用、权限控制或删除的事实应由 RAG 管理」。
- **注意 ICL 的两个隐藏成本**：原书指出「ICL 用示例、规则和当前状态实现零参数的即时适应，但随着上下文增长，延迟与费用也会上升」；再加上示例占位会挤压真正需要推理的空间。把这两个成本算进去后，你还会为一件事写 few-shot 吗？
- **把「领域知识」这个例子拆开**：稳定、规模大、需要形成内部表征的部分 → Mid-training；需要随时更新或给出原始出处的部分 → RAG。原书的表述是「如果事实需要频繁更新或必须给出原始出处，RAG 仍优于把知识写进权重」。
- **想想「程序约束」这个第三选项。** 本章的稳健系统组合里还有一项：「用程序固化确定性流程与硬约束」。转账审批规则这类需求，为什么答案既不是参数也不是 few-shot？
- **最后给出一条带条件的决策规则**，而不是一个偏好排序——写成「若 X 则走参数，若 Y 则走上下文，若 Z 则走程序」，并说明每条规则的失效条件。

### 思考题 3 ★★

> **原题**
>
> ★★ 模型蒸馏让小模型学习大模型的行为。按能力层次，被蒸馏的模型大致可分为三级——**Chat 模型**（单轮对话、直接作答）、**Reasoning 模型**（带长链思考再作答）、**Agentic 模型**（多轮调用工具、与环境交互）。分别蒸馏这三类模型，难点有什么不同？（提示：从“要蒸馏的到底是什么”入手——是输出的风格、完整的思考轨迹，还是与环境交互的决策策略；轨迹里哪些 token 该学、哪些是环境返回的不该学；以及成败信号出现得有多晚、有多稀疏。）

**提示思路**：

- **先按「监督信号的载体」分层**，而不是按模型规模分层。Chat 蒸馏的载体是**输出文本**；Reasoning 蒸馏的载体是**完整思考轨迹**（实验 8-9 给出口径：「以“问题 → `<think>` 思考轨迹 `</think>` + 最终答案”为训练对」）；Agentic 蒸馏的载体是**决策策略**——它甚至不全在文本里，还包含「何时调用、传什么参数、读到反馈后怎么改」。
- **第二层追问：轨迹里哪些 token 该学？** 实验 8-14 给出一条硬规则：「环境返回的 token 不是策略生成的，计算策略梯度时应屏蔽这些反馈 token，只对模型自己的思考和工具调用参数回传梯度。」把这条规则套到三级模型上，你会发现**只有 Agentic 一级存在「非模型产生的 token」**——这正是它独有的第一个难点。
- **第三层追问：成败信号有多晚、多稀疏？** Chat 一级信号立即；Reasoning 一级信号在轨迹终点，而且实验 8-9 还要额外做**拒绝采样过滤**（「否则错误的思考过程会被学生一并模仿」）；Agentic 一级信号在多轮之后，且还要面对信用分配——原书的问法是「一个客服 Agent 用了 10 轮对话解决了用户问题，最终获得好评——但这个好评该归功于第 2 轮的精准提问，还是第 7 轮的耐心解释？」
- **第四层：教师可得吗？** Reasoning 与 Agentic 蒸馏都要求拿到完整轨迹，而闭源思考模型存在「思维围墙」现象（改写或摘要 CoT）。请自己判断：这个约束把可行的教师集合缩小成了什么？
- **第五层：环境是不是蒸馏的一部分？** Agentic 一级的教师评分依赖它当时所处的环境。回想原书的警告：模拟器有偏差时，「教师对陌生偏差状态的评分也不可靠」。这一层在 Chat/Reasoning 上存在吗？
- **收尾时比较三级的「单位成本收益」**：从 Chat 到 Agentic，单条轨迹的成本在涨、可复用的监督密度在变，这正是本章为什么要把 On-Policy Distillation 提出来。

### 思考题 4 ★★★

> **原题**
>
> ★★★ 在多轮 Agent 交互中，奖励的归因（credit assignment）问题比单轮更严重——一个最终的成功或失败很难归因到第 3 轮还是第 7 轮的决策。你会如何设计奖励分配策略？

**提示思路**：

- **先把问题拆成两层**，因为它们的解法不同：其一是**奖励在哪里给**（终点 / 中间 / 两者），其二是**优势怎么算**（怎么把一条轨迹的分数摊回每一步）。本章给出的现成机制分别对应这两层——$R=O+\beta\Phi$ 属于前者，PPO 的价值网络与 GRPO 的组内比较属于后者。
- **第二层里有一条容易被忽略的口径**：多轮 LLM RL 通常把折扣因子设为 $\gamma=1$，「PPO 的价值网络或 turn-level 优势负责把终点反馈归因到较早的动作，GRPO 则把轨迹级优势均摊到生成 token，长轨迹上需格外注意信号稀释」。请想清楚：如果你用的是 GRPO，第 7 轮的决策与第 3 轮的决策在梯度上有什么区别？
- **加中间奖励之前先做两道门禁**。第一道是**可验证性**：只挂在确定性可判定的中间事件上（身份验证、工具参数、测试通过数、导航动作），而不是「这一步看起来有没有进展」。第二道是**可达性**：原书给的门禁是「先测信号可达性，再决定是否增加奖励维度」，因为纯结果奖励在全败组和全胜组都会产生零方差、没有梯度。
- **注意非对称验证器这个现实约束**：「检测“做了一个坏动作”便宜而可靠，证明“这一步确实朝着目标取得了有意义的进展”却很难。」这提示了一条务实的不对称策略——惩罚那一半通常可达，进展奖励那一半受可达性门控。
- **别忘了作弊面随维度增长**：「每增加一个评价维度，就增加一种被策略钻空子的可能。」你的归因设计越精细，被钻的空子越多——请给出你打算如何守住这条边界（隐藏测试？外部终止钩子？）。
- **最后把方案写成可执行的三段式**：结果项（保底、不可被替代）+ 路径项（只含具体动作的确定规则）+ 组内比较方式（谁跟谁比、如何恢复差异），并说明每一段在**全败组**和**全胜组**上分别会发生什么。

### 思考题 5 ★★★

> **原题**
>
> ★★★ 如果你有固定预算（比如 $10,000），要提升一个客服 Agent 的性能，你会如何在上下文与知识、Prompt/Skills、程序约束和参数训练之间分配预算？你的决策取决于哪些因素？

**提示思路**：

- **先诊断，再分配。** 本章的第一条决策顺序是「先排除不需要改权重的方案。Prompt、工具、代码约束、上下文管理能解决行为问题时不必训练」。在写下任何百分比之前，请先写出你的**缺口判断**：这个客服 Agent 缺的是底座（不会）、协议（不稳定）还是策略（好路径概率低）？
- **给四个预算科目各写一句「它买什么」**：上下文与知识买的是**可动态更新、可追溯的事实**；Prompt/Skills 买的是**可快速试错的行为规范**；程序约束买的是**确定性**（原书那句「长期稳定的转账审批规则也应由代码提供确定性保障，而不能只靠模型记忆」）；参数训练买的是**难以由外部规则完整表达的能力**（高维感知、生成风格、隐式决策策略）。

### 思考题 6 ★★★

> **原题**
>
> ★★★ 让模型在没有明确奖励函数、样本稀少的情况下自主学习，被一些人认为是后训练的终极目标。当前的 RL 训练方法距离这个目标还有多远？你认为下一个突破最可能来自哪个方向？

**提示思路**：

- **先把「终极目标」翻译成可检查的依赖清单**，否则你无法度量距离。当前配方至少依赖四件事：可靠且可重置的环境；能区分对错的奖励（原书的排序是「规则越确定，奖励越便宜、可复现，也越不容易被模型钻空子」）；组内有奖励差异；采样与训练的分布一致性。**逐条问：这一条能不能被去掉？**
- **把「样本稀少」与「奖励不明确」分开处理**，因为本章对它们各有一半答案。样本稀少侧的现成手段是提高单位交互的信息量——在轨蒸馏把一条 rollout 从「一个 0/1 信号」变成「约 $T$ 组逐 token 监督」；奖励不明确侧的现成手段是换监督来源——特权信息（标准答案、人工示范、领域文档）可以替代更强教师，且「不要求奖励一定能被自动验证」。
- **注意这些手段各自的硬前提**。OPSD 的前提是「学生至少要能进入教师可纠正的有效状态」，而且「如果模型拿着答案也讲不清过程，自蒸馏就没有额外信号」；模型模拟环境的前提是「模拟器的世界知识就是训练的天花板」，且「RL 会主动寻找并利用模拟器的漏洞」。把这些前提当作距离刻度：**每去掉一个人工给定的东西，就换来一个新的失效模式。**

### 思考题 12 ★★★

> **原题**
>
> ★★★ ReTool 的训练动态显示（见实验 8-14），少数超长响应会显著拖长整个训练周期——一批 rollout 里绝大多数已经生成完毕，却要等那几条最长的响应收尾，其间集群的 GPU 利用率很低。如何提升这种长尾响应场景下训练集群的资源利用率？

**提示思路**：

- **先量化，再优化**。你需要三个数字：batch 内**最长/平均响应长度比**、**GPU 空转时间占比**、以及**一个 step 的墙钟时间构成**。本章给了一个可直接套用的估算模板：「假设最慢 rollout 用时约 2,000 秒，随后梯度下降和优化器更新用时约 600 秒，那么一个 step 大约需要 $2{,}000+600=2{,}600$ 秒，即约 43 分钟。」注意这条式子的关键含义——**rollout 阶段的墙钟时间由最慢的那条决定**。
- **把可选手段按「作用在长度还是在调度」分成两类**，再逐条评估。作用在**长度**上：长度惩罚/预算控制、超时截断、尽早失败；作用在**调度**上：按长度分桶、连续批处理（continuous batching）、异步 rollout、把生成与训练拆成不同粒度的流水线。
- **每一条手段都有一笔代价要还**，本题的得分点在于你写出了哪些。长度惩罚与截断会**改变奖励语义**（可能惩罚正确但冗长的推理，而冗长本身有时是必要的）；异步 rollout 会引入 **staleness**，原书的提醒是「只要 rollout worker 落后了几个 checkpoint，数据就已经陈旧，训练在统计意义上也已经带有 off-policy（离轨）成分」。
- **把数值一致性这条约束也纳入考虑**：分桶、改变批大小、改变并行布局都会改变归约方式，而原书明确指出「批大小改变计算归约方式、破坏数值的 batch invariance，也已被直接观察到会把本应 on-policy 的 RL 变成隐式 off-policy」。也就是说，某个能让 GPU 更忙的调度改动，可能同时让你的训练悄悄变成 off-policy。请给出你的监控项（$\rho_t$ 的均值、分位数、最大值、近似 KL、被裁剪比例）。
- **区分「吞吐」与「有效吞吐」**。GPU 利用率高不等于训练有效：如果梯度被少数超长样本主导，或者所有算力都花在长尾上而短样本的组内比较信息被浪费，那么提高的只是空转率的分母。请给出一个能同时反映两者的代理指标。

### 思考题 13 ★★★

> **原题**
>
> ★★★ 用 LLM 模拟环境（如模拟搜索引擎、模拟用户）训练 Agent 时，Agent 钻空子的对象从 “真实环境的规则” 变成了 “模拟器本身的偏见与漏洞”。这类训练中可能出现哪些具体的 reward hacking 行为？又该如何防范？

**提示思路**：

- **先把攻击面按「环境扮演了谁」分类**，再逐类举例。模拟搜索引擎、模拟用户、模拟工具返回值、模拟整个环境动态——四类角色各有自己的可钻之处。举例时尽量落到**具体行为**而不是笼统的「钻空子」：它做了什么动作、骗过了谁、评分因此怎么变。
- **本章已经把两条机制分开了，请用它们分别解释现象**：「**reward hacking** 是钻规则或实现漏洞拿高分，**reward seeking** 则是模型先在心里建立一个“评判器会看什么”的模型，再按这个猜测调整行为。」后者在模拟环境里尤其危险——因为评判器本身就是被模拟出来的，它的偏好更容易被猜中。原书给的典型形态是「自行设置一个过于简单的检查，刚好通过就提前结束，交付物因此只满足代理指标而没有满足真实意图」。
- **注意这个问题在模拟环境里会自我放大**：原书明确写道「更糟的是，RL 会主动寻找并利用模拟器的漏洞，进行 reward hacking」。请解释这个放大链条是怎么形成的——这与真实环境里的漏洞利用有什么本质不同？
- **防范手段要有层次，不要只写「加人工审核」**。可从四个位置入手：**验证位置**（把判定搬出模拟器，交给确定性验证器、隐藏测试、状态断言、外部终止钩子）；**环境本身**（模拟器版本化、偏差审计、「用真实环境交互定期校准模拟器的偏差」）；**奖励结构**（路径约束惩罚具体违规动作——RLVP 的思路；结果奖励始终保留）；**评估侧**（对抗集、边界集与保留集、多模拟器一致性检查）。
- **正面回应那条上限判断**：「模拟器的世界知识就是训练的天花板，模拟器的系统性偏差会被策略照单全收。」这句话对防范方案意味着什么？如果模拟器本身有系统性偏差，仅靠更好的奖励规则能不能救？
- **收尾时区分「可检测的钻空子」与「不可检测的钻空子」**，并说明你的方案在哪一类上有效、在哪一类上只能靠混合真实交互兜底。原书给出的稳妥做法是「**混合**：用模型模拟承担大部分交互量，辅以真实环境的交互，并用真实环境交互定期校准模拟器的偏差」。
