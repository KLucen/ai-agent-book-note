## 实验 8-1 ★：Q-learning 在寻宝游戏中的表现

- **原书位置**：§「两种动作表示：经典 RL 设置与 LLM 的变长策略」（属 `[可选阅读]` 的「从经典 RL Agent 到现代 Agent」一节）
- **目的**：验证表格 Q-learning 的特性与局限。原书称「为了验证 Q-learning 的特性与局限，我们设计了一个**寻宝游戏环境**」，用一个无先验知识的 Agent 走通完整路径所需的交互量，为后文 LLM Agent 的样本效率建立对照基线。
- **前置条件**：
  - **依赖**：自建寻宝游戏环境；一套表格 Q-learning 实现。原书未给出代码路径，环境与算法均需自行实现〔推测〕。
  - **算力**：极低。原书写明「整个训练仅需不到 10 秒（仿真效率极高）」，单机 CPU 即可，不需要 GPU、不需要预训练模型。
  - **数据**：无外部数据。训练数据即环境自身产生的 episode——「episode 指一局完整的游戏，从开局到通关或失败算作一次」。
- **设计（控制变量）**：环境刻意设置三类挑战——「**隐藏机制**要求 Agent 自行发现钥匙和门的对应关系、武器效果和物品合成规则；**多步依赖**意味着完成任务需要正确的动作序列（最优解 11 步）；**稀疏奖励**意味着只有关键动作和最终胜利才有显著奖励，中间大部分步骤得不到任何反馈」。Agent 侧「使用标准参数配置，采用 ε-贪婪探索策略」。
- **操作步骤**：
  1. 实现寻宝游戏环境：定义钥匙—门的对应关系（隐藏）、武器效果与物品合成规则、11 步最优解对应的动作序列、稀疏奖励函数。
  2. 实现表格 Q-learning：为每个「状态-动作」维护价值估计，按贝尔曼方程 $Q^*(s,a)=r+\gamma\max_{a'}Q^*(s',a')$ 迭代更新。
  3. 采用 ε-贪婪探索策略——「大部分时间选当前最优动作，偶尔随机尝试，随着训练推进逐渐减少随机探索的比例」。
  4. 按 episode 连续训练并记录胜率曲线与 Q 表规模，对照 1000 / 5000 / 7000–8000 / 10000 episodes 四个观察点。
  5. 训练结束后核对 Agent 找到的是否为 11 步最优解，并记录最终 Q 表状态数。
- **关键代码或配置**：
  - 原书给出的唯一显式配置是「标准参数配置 + ε-贪婪探索策略」，未列出学习率、折扣因子 $\gamma$、ε 衰减表等具体数值；下表为复现所需记录的最小配置集〔推测〕，不是原书数值。

    ```text
    环境：寻宝游戏（隐藏机制 / 多步依赖最优 11 步 / 稀疏奖励）
    算法：表格 Q-learning（离轨策略）
    探索：ε-贪婪，ε 随训练推进递减
    观测点：1000 / 5000 / 7000-8000 / 10000 episodes
    记录项：胜率、Q 表状态数、是否命中 11 步最优解
    ```

- **预期结果与判读方法**（原书给出的学习曲线，逐条照录）：
  - 「**前 1000 episodes**：0% 胜率，Q 表仅 124 个状态，Agent 在盲目探索」；
  - 「**前 5000 episodes**：依然没有稳定胜利，Q 表 133 个状态」；
  - 「**7000-8000 episodes**：胜率从 34% 逐步升至 96%」；
  - 「**10000 episodes**：100% 胜率，Q 表 145 个状态，找到 11 步最优解」。
  - **判读要点**：胜率曲线呈「长期零分 → 突然爬升」的形态，且 Q 表规模增长极慢（124→133→145）——说明价值信号传播慢、必须反复强化；若你在 1000 episodes 就看到明显胜率，多半是环境太简单或奖励太密，对照价值就消失了。
- **常见陷阱**：
  - 把「10000 次试错只要 10 秒」误读为「这个方法很高效」——原书的重点恰好在反面：「在真实世界的 Agent 场景中——每次打电话有成本、每次操作浏览器有延迟、每次错误决策可能造成不可逆后果——10000 次试错是完全不可接受的」。
  - 把三项局限说成 MDP 数学框架的限制。原书明确澄清：「这些不是 MDP 数学框架本身的限制。函数近似、迁移学习和基于模型的 RL 可以处理更复杂的状态和知识迁移」。
  - 用随机环境的公式照抄确定性写法而忘记取期望（原书在贝尔曼方程处已提示「随机环境下需对下一个状态 $s'$ 取期望」）。
- **关键结论**：
  - 「这个**无先验知识的表格 Q-learning 实验**有三项局限：简单任务也需要大量交互，样本效率低；一个环境中的表格值难以直接迁移到另一个环境；每个新任务都要重新探索。」
  - 「使用预训练 LLM 策略的一个原因，正是可以利用已有知识，在更少的环境交互中做出有效决策。」
  - Q-learning「属于一种**离轨策略**（Off-Policy）方法……但仍要求充分覆盖相关状态—动作对，并满足适当的学习率与收敛条件；它并不是对任意数据分布都能自动收敛。」
- 〔精读批注〕这个实验的真正产物不是那条胜率曲线，而是**一条成本口径**：仿真里 10000 次交互 ≈ 10 秒，现实里同样的交互量不可支付。本章后面所有关于样本效率的论证（RLVP 恢复组内差异、在轨蒸馏把一条 rollout 变成 $T$ 组监督、ReTool 的 RL 训练时间是 SFT 的 200 倍以上）都建立在这个换算上。动手时建议顺手记下三个数字——单 episode 墙钟时间、达到 100% 胜率所需 episode 数、Q 表规模——它们是后面判断「这个任务该不该上 RL」的原始分母。

## 实验 8-2 ★★：传统 RL 与 LLM Agent 的对比研究

- **原书位置**：§「两种动作表示：经典 RL 设置与 LLM 的变长策略」（紧随实验 8-1）
- **目的**：在**同一个**寻宝游戏里对比无先验的表格 Q-learning 与携带海量预训练先验的 LLM Agent，量化「先验知识」对样本效率的贡献，验证「不是算法 > 环境 > 先验，而是先验 > 环境 > 算法」这一判断。
- **前置条件**：
  - **依赖**：与实验 8-1 完全相同的寻宝游戏环境；一个具备长链思考与工具调用能力的 LLM（原书使用 **Kimi K3**）；LLM 侧需要一层经验缓冲区（原书为「维护最多 50 条经验的缓冲区」）。
  - **算力**：无需训练。成本形态从「大量仿真交互」变成「少量 LLM 推理」——原书给出的对照是「Q-learning 跑 10000 局只需 10 秒，LLM Agent 一局却要 1-2 分钟」。
  - **数据**：无需训练数据；需要把游戏规则、可用动作与观察结果组织成模型可读的上下文。
- **设计（控制变量）**：环境、任务目标、成功条件三者与实验 8-1 保持一致，唯一变量是**策略主体**（表格 Q-learning vs LLM Agent）。这样可以把两组曲线之差归因到「是否携带先验」，而不用去争论算法优劣。
- **操作步骤**：
  1. 复用实验 8-1 的寻宝游戏环境与成功判定（11 步最优解、稀疏奖励）。
  2. 把 LLM Agent 接入环境：为它提供动作空间说明与每步观察，并维护「最多 50 条经验的缓冲区」。
  3. 让 LLM Agent 从零开始跑一局，逐步记录它的动作序列与每步的推理依据。
  4. 对照 Q-learning 的训练曲线，比较两条路径在「首次通关所需交互数」与「成功所需的先验来源」上的差异。
  5. 改变游戏规则（如钥匙—门对应关系），观察 Q-learning 需要重新训练而 LLM Agent 能否靠推理直接适应。
- **关键代码或配置**：
  - 原书未给出 LLM Agent 的提示词或代码，只给出可复现的关键参数与架构关系：

    ```text
    Agent：Kimi K3
    记忆：最多 50 条经验的缓冲区
    环境：与实验 8-1 相同的寻宝游戏（隐藏机制 / 11 步最优解 / 稀疏奖励）
    对照：表格 Q-learning（实验 8-1 的曲线）
    记录项：每步动作 + 推理依据、首次通关步数、规则变更后的适应情况
    ```

  - 架构对比见原书图8-7。

  ![图8-7 Q-learning 与 LLM Agent 在寻宝游戏中的架构对比](../images/fig8-7.svg)

  **图8-7 解读**：该图并置两种 Agent 在同一个寻宝游戏中的架构（原书 实验 8-2）——左侧 Q-learning 只有「状态—动作」价值表，靠 ε-贪婪在环境里反复试错积累统计关系；右侧 LLM Agent 把语义理解、经验缓冲区与推理链放在环境之外，环境交互只用来验证推理假设。两者的差别不在学习算法，而在策略里是否已经带有先验知识。

- **预期结果与判读方法**：
  - **预期结果**：「**LLM Agent 第一局就在 18 步内通关**」，三个阶段的行为分别是——「**前期（有目的的探索）**：拿起生锈的剑（“武器总比空手好”），系统探索地图，发现北门被锁后推理 “需要找钥匙”，转而探索储藏室，先后取得红钥匙与魔法水晶。**中期（机制理解与主动合成）**：理解 “钥匙自动使用” 规则，并预判生锈的剑不足以对付守卫，于是在第 8 步主动合成银剑。**后期（执行与纠错）**：持银剑向北，第 13 步击败强守卫，其间夹杂一两步无效尝试（重复挥剑/回退），最终在第 18 步取得巨龙宝藏。」
  - **判读要点**：看动作序列里是否存在**跨步的语义依赖**（「武器总比空手好」→ 主动合成银剑）。Q-learning 无法产生这种句子级的因果链，它只会把「门」「钥匙」「剑」当作无意义的符号组合。另外要接受 18 步 > 11 步：LLM Agent 也有无效尝试，先验压缩的是搜索空间，不是消除试错。
- **常见陷阱**：
  - 用「一局 1-2 分钟 vs 10000 局 10 秒」直接判 LLM 更贵。原书的结论是成本口径要换成现实口径：「在现实任务中，每次交互的时间、金钱和风险成本远超纯计算成本，所以单看 GPU 时间并不公平」。
  - 把结论说成「LLM 的学习算法更好」。原书明确否定：「LLM Agent 的成功不是因为拥有更好的“学习算法”，而是因为携带了海量先验知识」。
  - 只跑一局就下结论——本实验是单局对照，缺少重复次数与方差信息，不宜外推为「LLM 稳定优于 Q-learning」。
- **关键结论**：
  - 「这展现了语义理解与符号映射之间的根本差异。LLM Agent 理解了游戏的概念结构，每一步都有目的和逻辑支撑。」
  - 「当游戏规则变化时，Q-learning 需要完全重新训练，LLM Agent 却能通过推理直接适应。由此可以得出实用的设计原则：在仿真成本低、可大量重复的场景中，传统 RL 仍然有价值；在交互成本高、需快速适应的现实场景中，LLM Agent 的样本效率更为实际。」
- 〔精读批注〕本实验最值得带走的是一个**选型判据**：交互便宜就留给 RL，交互昂贵就让先验先上场。它与本章后文并不矛盾——SimpleVLA-RL 用一条演示轨迹 SFT 冷启动后，RL 把成功率从 17.3% 拉到 91.7%，正是「先验打底 + 仿真里放开试错」的组合形态。动手时建议把 Kimi K3 换成同族但更小的模型再跑一遍，观察「先验缩水」之后通关步数与无效步数如何变化——那是先验价值的直接度量。

  | --- | --- | --- | --- |

  - [ ] 待尝试变体：换更小的模型，测先验缩水后的通关步数；

## 实验 8-3 ★★：从头训练 LLM——算法改进的威力

- **原书位置**：§「模型预训练基础 `[可选阅读]`」
- **目的**：在**固定的小规模预算**下走完「预训练 → SFT → 偏好优化」的完整训练流程，验证本章第二条规律的底座部分——**算法改进与架构创新比单纯扩大规模更具性价比**。
- **前置条件**：
  - **依赖**：MiniMind 2 训练代码（一亿参数级）；需要在消费级 GPU 上可跑的完整流水线，含预训练、SFT 与偏好优化三个阶段。
  - **算力**：消费级 GPU。原书给出「总训练约 14 小时，成本约 34 美元」。
  - **数据**：预训练语料 + SFT「输入—输出」示范对 + 偏好数据（用于偏好优化阶段），原书未给出具体数据规模〔推测〕。
- **设计（控制变量）**：模型规模固定在**一亿参数**，变量是**两项算法优化**——**QK Norm** 与 **Muon 优化器**；观测指标是收敛速度与生成质量，并逐阶段检视能力变化。
- **操作步骤**：
  1. 准备 MiniMind 2（一亿参数）的完整训练流程，在消费级 GPU 上跑通。
  2. 引入两项算法优化：QK Norm 与 Muon 优化器。
  3. 执行预训练阶段，检验模型能否回答事实性问题（原书例：「世界上最高的山峰」）。
  4. 执行 SFT 阶段，检验指令遵循与输出格式是否改善。
  5. 执行偏好优化阶段，检验事实错误与不自然表达是否减少。
  6. 对照未引入两项优化的基线，比较收敛所需步数与最终生成质量。
- **关键代码或配置**：
  - 原书只点名两项优化与预算，未给超参；可记录的最小配置如下：

    ```text
    模型：MiniMind 2，约 1 亿参数
    算法优化：QK Norm + Muon 优化器
    阶段：预训练 → SFT → 偏好优化
    预算：约 14 小时，约 34 美元（消费级 GPU）
    观测：收敛速度（相对基线的倍数）、各阶段生成质量
    ```

- **预期结果与判读方法**：
  - **预期结果**：原书写明「通过引入两项算法优化（QK Norm 和 Muon 优化器），收敛速度提升 3 倍，生成质量显著改善」；各阶段效果为——「预训练后模型可以回答“世界上最高的山峰”等事实性问题，但格式不规范；SFT 后指令遵循与输出格式显著改善，能按期望方式组织答案；偏好优化进一步减少了事实错误与不自然表达」。
  - **判读要点**：把「阶段」当作自变量来看曲线——预训练解决**有没有知识**，SFT 解决**格式与指令遵循**，偏好优化解决**表达与事实错误**。若某个阶段跑完指标不动，对照本章的缺口分类表（表8-4）先判断缺的是知识、协议还是策略，再决定是否加预算。
- **常见陷阱**：
  - 把「一亿参数够用」误当成通用结论。原书明确提示边界：「一亿参数的模型仍有明显局限（复杂问题容易出错），但启示是：**在固定的小规模预算下，算法改进比单纯堆规模更具性价比**」——限定语是「固定的小规模预算下」。
  - 跳过偏好优化直接看 SFT 结果，会把「表达不自然」误判为「知识不足」。
- **关键结论**：

## 实验 8-4 ★★：自己训练 VLM

- **原书位置**：§「模型预训练基础 `[可选阅读]`」（紧随实验 8-3）
- **目的**：理解**跨模态对齐**的核心挑战——「让“看到的”和“说出来的”对应起来」；并验证「冻结 LLM + 只训练投影层」这一低成本路线能否在避免灾难性遗忘的前提下完成模态对齐。
- **前置条件**：
  - **依赖**：三组件架构（视觉编码器 + 投影层 + 语言模型）；视觉编码器原书指定为「如 CLIP」，且**参数固定**。
  - **算力**：比实验 8-3 更集中在**视觉—语言对齐**环节，因为唯一从头训练的部分是轻量投影层；原书未给出具体时长与成本〔推测〕。第二阶段要解冻 LLM 做 SFT，算力需求随之上升。
  - **数据**：预训练阶段需要图像—文本对用于对齐；SFT 阶段需要「高质量图像-描述对」。
- **设计（控制变量）**：架构固定为「视觉编码器 + 投影层 + LLM」，**变量是哪些参数可训练**——第一阶段只训练投影层（编码器固定、LLM 冻结），第二阶段解冻 LLM 做 SFT。这样才能把「跨模态对齐」与「语言能力保持」两件事分开观察。
- **操作步骤**：
  1. 搭建三组件：视觉编码器（CLIP 等，参数固定）→ 投影层（轻量级，唯一从头训练的部分）→ 语言模型。
  2. 冻结 LLM，只用图像—描述对训练投影层，让它「将视觉特征映射到语言模型能理解的表示空间」。
  3. 完成预训练对齐后，解冻 LLM，用高质量图像—描述对做 SFT。
  4. 对比解冻前后生成的描述在**详细程度与准确性**上的变化。
  5. 检查灾难性遗忘：确认冻结阶段与解冻阶段之后，语言模型原有的语言能力是否被破坏。
- **关键代码或配置**：
  - 原书给出的配置是策略级的，不是超参级的：

    ```text
    视觉编码器：CLIP 等，参数固定
    投影层：轻量级，唯一从头训练的部分
    语言模型：第一阶段冻结，第二阶段解冻并做 SFT
    数据：图像—描述对（SFT 阶段要求高质量）
    观测：描述详细程度与准确性、灾难性遗忘
    ```

  - 架构见原书图8-9。

  ![图8-9 视觉语言模型（VLM）架构](../images/fig8-9.svg)

  **图8-9 解读**：该图给出 VLM 的三组件骨架（原书 实验 8-4）——视觉编码器把图像压成语义特征，投影层充当「视觉特征与语言模型之间的“翻译官”」，语言模型负责生成描述文本。原书特别标出「训练采用“冻结 LLM + 只训练投影层”的策略，以避免灾难性遗忘」，因此图中可训练参数的边界只落在投影层上。

- **预期结果与判读方法**：
  - **预期结果**：「预训练对齐后再解冻 LLM，用高质量图像-描述对做 SFT，描述的详细程度与准确性显著改善。」

- **常见陷阱**：
  - 一上来就全参微调，失去「冻结 LLM 以避免灾难性遗忘」这一对照，也就无从判断遗忘是否发生。

- **关键结论**：
  - 「本实验揭示了多模态模型训练的基本范式：复用单模态预训练成果，通过训练一个轻量投影层实现跨模态对齐——高效且可扩展，但投影层的表达能力有限，可能成为跨模态深层理解的瓶颈。」

## 实验 8-5 ★★：继续预训练学习新语言

- **原书位置**：§「Mid-training：补知识与基础能力」
- **目的**：在**已完成预训练**的模型上注入一门新语言（韩语）的能力，并同时暴露继续预训练的两面性——目标分布可以写进参数，但通用能力可能被侵蚀。原书用这个实验把 Mid-training 与 SFT 的职责分界讲清楚：「Mid-training 先补韩语知识与语言能力，SFT 再教模型如何用韩语接受指令和组织回答。」
- **前置条件**：
  - **依赖**：一个主要用英语预训练、对韩语几乎没有理解能力的基座模型——原书指定 **Mistral 7B v0.3**；外加一个 SFT 阶段所需的韩语指令数据。
  - **算力**：原书未给出时长与卡型，但明确给出成本判断——「模型已具备通用表征，只需适应新的数据分布，成本远低于从头训练」；同时提醒「对大模型做全参数 Mid-training 的计算和遗忘风险都明显高于小规模 SFT」〔算力数值未给出〕。
  - **数据**：**约 80% 韩语 + 20% 英语**的混合语料用于继续预训练；韩语指令数据用于收尾 SFT；英语保留集用于监测遗忘。
- **设计（控制变量）**：基座、词表与训练目标都不变（仍是「预测下一个词」），**变量是数据分布**——把语料换成目标语言，并混入英语作为抗遗忘配比。原书特别声明该配比的适用范围：「这只是该实验的选择，不是通用默认值」。
- **操作步骤**：
  1. 选定基座 Mistral 7B v0.3，先记录它在韩语上的基线表现（预期「对韩语几乎没有理解能力」）。
  2. 构造混合语料：约 80% 韩语 + 20% 英语，用于缓解灾难性遗忘。
  3. 用与预训练相同的下一个词任务做继续预训练（Mid-training）。
  4. 用韩语指令数据做 SFT，把「会韩语」转成「能用韩语接受指令并组织回答」。
  5. 做韩语盲评，同时测量英语能力，检查是否出现遗忘。
- **关键代码或配置**：

  ```text
  基座：Mistral 7B v0.3（主要用英语预训练）
  阶段一：Mid-training —— 继续预训练，目标仍为预测下一个词
  数据配比：约 80% 韩语 + 20% 英语（本实验的选择，非通用默认值）
  阶段二：SFT —— 韩语指令数据
  评估：韩语盲评、英语保留集
  ```

- **预期结果与判读方法**：
  - **预期结果**：韩语能力被成功注入，韩语盲评改善；同时「英语能力却有下降」。
  - **判读要点**：必须**同时**看两条曲线——只看目标语言会得出「Mid-training 很划算」的片面结论，只看保留集则会否定整条路线。原书给出的判读原则是：「继续预训练可以把目标分布写进参数，但不能免除保留集、事实评估和数据质量审计。」
- **常见陷阱**：
  - 把 80/20 当成通用默认配比照搬。
  - 指望 Mid-training 单独解决「能不能被问答访问」的问题。原书在 Mid-training 一节已说明：「Mid-training 降低了领域文本的语言模型损失，也不保证模型会自动按用户问题取出知识」，稳健配方是「Mid-training 吸收知识与能力 → 小规模 SFT 建立输出格式 → 有非零成功率后再 RL」。
  - 只做盲评不做事实评估——盲评能测流畅与风格，测不出事实错误。
- **关键结论**：
  - 「它把两种职责分得很清楚：Mid-training 先补韩语知识与语言能力，SFT 再教模型如何用韩语接受指令和组织回答。」
  - 「本实验也说明继续预训练可能带来的灾难性遗忘问题：韩语最终阶段的盲评分改善，英语能力却有下降。」
  - 与实验 8-1／8-2 的呼应：Mid-training 之所以值得，是因为「继续预训练……成本远低于从头训练」。

## 实验 8-6 ★★★：语音 SFT——从 “声音复制” 到 “副语言建模” `[扩展实验]`

- **原书位置**：§「SFT（监督微调）」（四个 SFT 实验的第一个）
- **目的**：展示 SFT 在**表达型任务**中到底固化了什么。原书的结论句给出了答案：「SFT 在表达型任务中固化的是风格控制协议与结构化表达习惯，而非事实知识或复杂思考。」实验中并列两条技术路线，用于对比「音色一致性」与「副语言现象」两种目标。
- **前置条件**：
  - **依赖**：两条独立路线各自的模型与数据管线——**Orpheus**（语境提示 voice cloning，需把声音波形压缩为 token 序列）与 **Sesame**（副语言标记建模，需定义 `<laugh>`、`<sigh>` 等特殊标记）。
  - **算力**：原书未给出〔推测〕；语音数据带宽高于文本，属中高成本。
  - **数据**：多说话者的语音数据（保证音色多样性）+ 带副语言标记标注的语音数据。原书强调「关键在于训练数据的多样性和标注质量」。
- **设计（控制变量）**：同一目标（把「声音风格与表达习惯」写入参数），两种实现——**Orpheus 走音色条件化**，「通过拼接同一说话者的参考音频，让模型学会“用这个人的声音说话”，实现跨句音色一致」；**Sesame 走显式标记**，「将笑声、叹气等副语言现象抽象为 `<laugh>`、`<sigh>` 等特殊标记，训练模型学会“看到标记就发出对应的声音”」。
- **操作步骤**：
  1. 选定路线（Orpheus 或 Sesame，或两条都跑做对照）。
  2. 若走 Orpheus：把声音波形压缩为 token 序列，构造「参考音频 + 待合成文本」的样本对，训练跨句音色一致性。
  3. 若走 Sesame：定义副语言标记表（`<laugh>`、`<sigh>` 等），在语音数据上标注这些现象的位置，构造「标记 → 对应声音」的训练对。
  4. 做多说话者评测：同一文本换不同参考音频，检查音色是否跟随参考。
  5. 做新情境评测：在训练未出现的语境里触发副语言标记，检查是否自然。
- **关键代码或配置**：

  ```text
  Orpheus：声音波形 → token 序列；拼接同一说话者的参考音频；目标 = 跨句音色一致
  Sesame：副语言标记 <laugh> <sigh> …；目标 = 看到标记就发出对应声音
  数据要求：多说话者（避免所有人一个腔调）、标记标注准确
  观测：音色一致性、副语言自然度、是否出现「机械笑」
  ```

- **预期结果与判读方法**：
  - **预期结果**：两条路线都能把风格与表达习惯固化进参数；风险点是训练数据中说话者过少导致的「一个腔调」，以及标记过拟合产生的「机械笑」。
  - **判读要点**：判读时区分**音色**与**内容**两条通道——本实验的成功标准是「用这个人的声音说话」，而不是「说对了什么」。若换一段参考音频后音色不变，说明条件化没有生效；若每一句结尾都有笑声，说明标记过拟合。
- **常见陷阱**：
  - 训练数据说话者过少——原书列为第一种常见失败模式：「训练数据中说话者过少导致所有人听起来一个腔调」。
  - 标记过拟合——原书对它的解释是「模型死记硬背了训练样本的细节，遇到新情况反而表现更差」，表现为「机械笑」。
  - 期待 SFT 教会模型复杂思考或事实知识。原书在 SFT 一节开头已给出边界：「SFT 的核心价值不在于注入新知识，而在于**固化输出格式**」。
- **关键结论**：
  - 「两者思路不同」（Orpheus 走参考音频条件化，Sesame 走标记抽象），但共同点是都在固化**风格控制协议**。
  - 本实验属于本章 4 个 SFT 实验之一，共同特征是「把稳定的映射与协议写进参数」：「语音 SFT 固化风格控制协议，多语言 SFT 固化思考组织模板，蒸馏 SFT 固化输入到输出的直接映射」。
- 〔精读批注〕`[扩展实验]` 标记意味着它更像方向性演示而非可复现配方，但这个实验提供了一个**通用判据**：凡是「风格 / 语气 / 表达习惯」类需求，走 SFT 都是合适的；凡是「事实 / 知识」类需求，SFT 都是错的工具。它同时预告了本章的失败模式清单——数据中的说话者多样性对应「训练数据质量低下」，标记过拟合对应「过度训练导致泛化下降」。

## 实验 8-7 ★★★：多语言思考——让模型用任意语言思考 `[扩展实验]`

- **原书位置**：§「SFT（监督微调）」（四个 SFT 实验的第二个）
- **目的**：验证 SFT 能否把**思考的组织语言**变成可控变量。原书的问题陈述是：「大多数思考模型只会用英语“思考”：不管你用什么语言提问，模型内部的思维链几乎都是英文的，因为训练数据中高质量的思考示范基本都是英语写的。本实验的目标很简单——让模型能够用指定的语言进行思考。」
- **前置条件**：
  - **依赖**：一个支持系统指令与思维链输出的开源思考模型——原书指定 **gpt-oss-20b**；需要能在系统指令中注入 `reasoning language: …` 开关。
  - **算力**：20B 量级 SFT，单机多卡可完成；原书未给出时长与卡型〔推测〕。
  - **数据**：英语、西班牙语、法语等几种语言的思考样例；**训练数据中完全没有中文**（这是本实验的关键设计）。
- **设计（控制变量）**：基座、SFT 算法、数据规模都不变，**唯一变量是「思考语言」这一条件**，并被拆成两面来看——训练侧给的是英语/西语/法语样例，测试侧却要求模型用**训练中从未出现的中文**思考。这是刻意构造的零样本跨语言泛化测试。
- **操作步骤**：
  1. 准备 gpt-oss-20b 与一套系统指令模板，在指令中加一句 `reasoning language: German`（或其他语言）。
  2. 用英语、西班牙语、法语等几种语言的思考样例做 SFT（注意：样例里**不含中文**）。
  3. 训练完成后，把 `reasoning language` 设为 `Chinese`，向模型提问并检查思维链的语言。
  4. 记录中文思维链的完整性（是否只是翻译式套话，还是完整的推理步骤）。
  5. 做归因对照：先用多语言预训练基座（未做本 SFT）测试能否切到指定语言思考，判断这是 SFT 新学的能力还是被激活的既有能力。
- **关键代码或配置**：

  ```text
  基座：gpt-oss-20b
  系统指令：reasoning language: German（可替换为其他语言）
  训练数据：英语 / 西班牙语 / 法语等思考样例（完全没有中文）
  测试：reasoning language: Chinese
  观测：思维链语言、中文推理完整性
  ```

- **预期结果与判读方法**：
  - **预期结果**：模型能用中文进行完整的思维链思考，尽管训练数据中没有任何中文。
  - **判读要点**：原书给出了明确的归因纪律——「需要注意，这并非 SFT 本身的泛化能力。多语言预训练已经在模型中建立了跨语言的共享表征空间，SFT 只是激活了这种预训练时已有的跨语言能力。」判读时要看**推理步骤是否完整**（拆分问题、验算、回溯），而不只是看语言标签。
- **常见陷阱**：
  - 把零样本跨语言泛化记成「SFT 学会了新语言」。原书明确否定；正确表述是「激活了预训练时已有的能力」——这与 Mid-training 实验 8-5 的分工正好互补（8-5 用继续预训练**注入**语言，8-7 用 SFT **激活**已有语言）。
  - 把 `reasoning language` 当成一个通用可移植的开关。它是一个被训练出来的条件化行为，换基座后需要重新训练该映射。
  - 忽略训练数据中「思考示范都是英语」这一前提——如果连英语思考示范都不足，本实验的对照组不成立。
- **关键结论**：
  - 本实验属于「把稳定的映射与协议写进参数」这一类：「多语言 SFT 固化思考组织模板」。
  - 思考**语言**与思考**内容**是两件可分开处理的事；控制前者的成本远低于重训语言能力。
- 〔精读批注〕这是全章性价比最高的一个 SFT 实验范式：**用条件化开关把一个连续的大能力裁成可控的分支**。它与实验 8-10 的 AdaptThink 形成姊妹关系——8-7 教模型「用指定语言思考」，8-10 教模型「该不该思考」；两者都是把**元决策**（怎么思考）从**内容**（思考什么）里剥离出来写进参数。动手时建议顺手记录一个数字：把 `reasoning language` 设为训练未见语言时，思维链长度与英语提问时的比值——它反映条件化是否真的改变了计算路径。

## 实验 8-8 ★★：Prompt 蒸馏——以更小开销复现可用能力

- **原书位置**：§「SFT（监督微调）」（四个 SFT 实验的第三个）
- **目的**：把「长提示 + 思考型教师」的行为压缩到「短提示/无提示 + 非思考学生」中，验证蒸馏能否在保持输出质量的同时显著降低延迟与费用。
- **前置条件**：
  - **依赖**：一个思考型大模型作为教师（需在完整提示与思考模式下运行）；一个更小的学生模型作为训练目标。
  - **算力**：教师侧推理成本是主要开销（学生训练本身为常规 SFT 规模）；原书未给出具体数值〔推测〕。
  - **数据**：教师生成的高质量答案，**只保留用户输入与最终结论，丢弃冗长提示与中间思考过程**。
- **设计（控制变量）**：输入与最终输出保持同一分布，被压缩掉的是**过程**与**提示**两个维度。原书明确本实验可沿两个维度进行：「“大到小”（用中小模型替代大模型，在成本和质量之间取得折中）和“思考到非思考”（同等规模下把显式 CoT 折叠为隐式参数化知识，获得 20-30 倍的响应速度提升）」，且「两者并不冲突，在生产环境中经常同时使用」。
- **操作步骤**：
  1. 选定任务并写出完整的长系统提示（原书口径：数千甚至上万 token）。
  2. 让思考型教师在该提示与思考模式下生成答案。
  3. 构造训练数据：只保留**用户输入**与**最终结论**，丢掉长提示与中间思考 token。
  4. 用这批数据 SFT 学生模型，使其学会「直接给出结论」。
  5. 在同一输入集上对比学生与教师的输出质量，并测量延迟与费用。
  6. 补充边界测试：在长尾输入上比较学生与教师的错误模式，检查是否继承了教师的系统性错误。
- **关键代码或配置**：

  ```text
  教师：思考型大模型（完整长提示 + 思考模式）
  学生：常规模型（短提示 / 无提示 + 非思考）
  训练数据：{用户输入, 最终结论}  —— 丢弃长提示与中间思考
  两个蒸馏维度：大到小、思考到非思考（同规模下约 20-30 倍响应速度提升）
  观测：输出质量、延迟、费用、长尾错误继承情况
  ```

- **预期结果与判读方法**：
  - **预期结果**：「蒸馏后在相同输入上接近教师的输出质量，同时因为不需要处理冗长提示和思考 token，延迟与费用显著降低。」
  - **判读要点**：分两条曲线看——**质量差**（学生 vs 教师在目标分布上的差距）与**成本比**（延迟/费用的下降幅度）。原书给出的适用边界很明确：「当产品形态稳定、输入分布可预期、成本约束明显时，Prompt 蒸馏是很好的优化手段；而在探索期或任务尚未定型的阶段，保留显式思考与可编辑的提示工程仍是快速试错的核心。」
- **常见陷阱**：
  - 「蒸馏会继承教师的边界——若教师在长尾分布上有系统性错误，学生会进一步硬编码这些错误；若教师依赖工具来确保正确性，单纯的输出蒸馏会失去工具带来的鲁棒性。」
  - 在产品形态还没稳定时就上 Prompt 蒸馏：把还在演进的提示策略过早冻进参数，后续每次改需求都要重训。
  - 把「丢弃思考过程」与实验 8-9「保留完整思考轨迹」搞混——两者的数据形态完全相反。
- **关键结论**：
  - 蒸馏维度的可组合性：大到小 + 思考到非思考，可以叠加使用。
  - 蒸馏的本质是**把可编辑的提示工程换成不可编辑的参数**，其代价是适应性下降。
- 〔精读批注〕本实验的对偶是实验 8-10：Prompt 蒸馏先把「需要思考的任务比例」压下来，AdaptThink 再优化剩余任务的触发策略，原书称之为「快—慢双系统」。两者合起来给出一条工程路线——**先减少必须走慢路径的流量，再优化慢路径本身的触发条件**。这条路线也是判断「该不该上蒸馏」的实用判据：先量一量你的流量里有多大比例其实不需要思考。

## 实验 8-9 ★★★：思维链（Chain of Thought, CoT）蒸馏

- **原书位置**：§「SFT（监督微调）」（四个 SFT 实验的第四个）
- **目的**：与实验 8-8 相反——把强教师模型的**完整思考轨迹**转移给学生模型，验证「同等参数量下可恢复教师 70%–80% 的能力」这一量级，并为「不追求刷新前沿、但寻求自主可控」的团队给出跟随者策略。
- **前置条件**：
  - **依赖**：一个**开源的**强思考模型作为教师，必须能拿到完整思维链。原书解释了为什么不能用闭源模型：「一些闭源思考模型（如 OpenAI o 系列、Gemini 系列）在思考时会生成内部思维链，但用户看到的并非原始思考过程——厂商出于防蒸馏、安全和产品体验等考虑，通常会在输出前对 CoT 进行改写或摘要，最有价值的原始思考过程被隐藏在 API 之后」；可行的教师是「DeepSeek V4、Kimi K3、GLM 5.2 等模型直接公开完整思维链」。还需要规则验证器（过滤最终答案错误的轨迹）。
  - **算力**：7B 量级标准 SFT。原书未给出卡型与时长〔推测〕。
  - **数据**：从目标任务分布（如数学、代码）采样问题，由教师生成完整的「思考 + 答案」轨迹，再用规则验证器过滤掉最终答案错误的轨迹。
- **设计（控制变量）**：三步流程——**采集轨迹 → SFT 训练 → 对比评估**。原书对训练对的格式规定得很具体：「以“问题 → `<think>` 思考轨迹 `</think>` + 最终答案”为训练对，对小模型（如 7B 量级）做标准 SFT」；第三步则「在同一基准上对比蒸馏前后的学生模型与教师模型，衡量能力恢复比例」。
- **操作步骤**：
  1. **采集轨迹**：从目标任务分布采样问题，用开源教师模型生成完整的「思考 + 答案」轨迹。
  2. **验证过滤**：用规则验证器过滤掉最终答案错误的轨迹——「否则错误的思考过程会被学生一并模仿」。这一步即**拒绝采样（Rejection Sampling）**，用它构造的数据做 SFT 就是**拒绝采样微调（RFT）**。
  3. **SFT 训练**：按 `问题 → <think> 思考轨迹 </think> + 最终答案` 组装训练对，对 7B 量级小模型做标准 SFT。
  4. **对比评估**：在同一基准上对比蒸馏前后的学生模型与教师模型，计算能力恢复比例。
  5. **轨迹质检**：检查学生轨迹中是否出现「教师式的反思、回溯与验算行为」。
  6. **许可确认**：使用前确认教师模型许可证对蒸馏产物的授权条款。
- **关键代码或配置**：

  ```text
  教师：开源思考模型（DeepSeek V4 / Kimi K3 / GLM 5.2 等，公开完整思维链）
  ① 采集：目标任务分布采样 → 教师生成「思考 + 答案」轨迹
  ② 过滤：规则验证器剔除最终答案错误的轨迹（拒绝采样 → RFT）
  ③ 训练对：问题 → <think> 思考轨迹 </think> + 最终答案
  ④ 学生：7B 量级标准 SFT
  ⑤ 评估：同基准对比学生/教师，算能力恢复比例
  ```

- **预期结果与判读方法**：
  - **预期结果**：「对能力较强的教师模型进行 CoT 蒸馏，在同等参数量下可恢复教师 70%–80% 的能力」；「蒸馏后的学生模型在数学/代码基准上相对蒸馏前显著提升，且思考轨迹中出现教师式的反思、回溯与验算行为。」
  - **判读要点**：不要只看最终答案准确率——**轨迹形态**是更早期的信号。若学生答对率上去了但轨迹里没有回溯与验算，说明它学到的是答案分布而非思考过程；这类学生一旦遇到更难的题就会退化。
- **常见陷阱**：
  - 不做过错滤就用轨迹训练：「错误的思考过程会被学生一并模仿」。
  - 低估蒸馏的代价：「学生会继承教师的系统性错误和冗长思考习惯（后者可结合实验 8-10 的 AdaptThink 思路做二次优化）」。
  - 在这件事上过度用力。原书写得很直白：「**对绝大多数做后训练的人来说，根本不需要去蒸馏闭源模型的思维链。** 当前最先进的开源模型与 SOTA 闭源模型的差距并没有想象中大；教师模型只需要 “明显高于学生”，不需要 “全球第一”。如果你要后训练的是 200B 及以下规模的模型，用开源 SOTA 模型当教师已经完全够用。」
  - **工具侧的坑（原书「实验现场」实录）**：作者最初使用由 GPT-5.6-Sol 驱动的 OpenAI Codex 编写实验代码，「但当任务明确涉及模型蒸馏时，Codex 拒绝继续执行」；切换到 Claude Opus 5 驱动的 Claude Code「也遇到了同样的拒绝」；「最终，作者使用 Kimi K3 完成了实验代码和后续运行」。原书的解释是：「模型蒸馏与正常的监督微调在技术上高度相似，但在厂商的安全与产品策略中，它也可能与模型提取、能力复制和知识产权保护联系起来，因此成为一个敏感类别。」——**排期时要为代码生成工具的拒绝留出切换成本**。
- **关键结论**：
  - 「对于不追求刷新前沿能力边界、但寻求自主可控模型的团队，这是最务实的跟随者策略。」DeepSeek-R1 发布时同步开源的蒸馏小模型（用 R1 的思考轨迹对 Qwen、Llama 系列做 SFT）正是代表路线。
  - RFT 的定位：「它介于纯 SFT 与 RL 之间：不训奖励模型、不做策略梯度，只靠“从多条采样中拒绝错的、留下对的”来提升数据质量，是可验证任务上性价比极高的数据构造手段。」
  - 本章「思维围墙」现象的背景说明：闭源模型改写 CoT 的动机包括防蒸馏、安全和产品体验。
- 〔精读批注〕本实验与「实验现场」那段合起来，构成一章里少见的**工程约束记录**：技术方案可行 ≠ 工具链可执行。它同时给出了本章最实用的一个决策规则——**教师只需「明显高于学生」，而非「全球第一」**。这与表8-4 的判据互补：选教师时看的是能力差是否足够产生有效监督信号，而不是排行榜位置。

## 实验 8-10 ★★：AdaptThink——学会 “何时不思考”

- **原书位置**：§「单轮强化学习：记忆与泛化的对照」（第一个实验）
- **目的**：用 RL 训练模型**自适应地选择是否思考**。原书先给出待验证的直觉：「大型思考模型（如 OpenAI o1、DeepSeek-R1）对所有问题都会生成冗长的思维链，在简单问题上造成不必要的开销。实验首先验证了一个直觉：**NoThinking 模式**（通过 `<think></think>` 跳过思考）在简单问题上性能相当甚至更好，只有面对困难问题时 Thinking 的优势才显现出来。」
- **前置条件**：
  - **依赖**：一个支持 `Thinking/NoThinking` 双模式的基座；自定义的约束优化目标与重要性采样策略。
  - **算力**：**8×NVIDIA H100 80GB**（原书明确给出，来自公开 W&B 主运行 `wubbn5tj`）。累计训练耗时 **36.92 小时**（跑到 step 410）。
  - **数据**：MATH500、GSM8K、AIME（用于观测 mean@16）三套数学评测集；训练数据原书未单列〔推测〕。

## 实验 8-11 ★★：GeneralPoints——单轮 RL 的 “记忆与泛化” 对照

- **原书位置**：§「单轮强化学习：记忆与泛化的对照」（第二个实验，也是全章的核心对照实验）
- **目的**：系统量化「SFT 记忆、RL 泛化」。原书写明其定位：「本实验的核心贡献，是在有限的 GeneralPoints 设置中系统量化了 SFT 的过拟合倾向与 RL 更好的分布外表现，并在纯语言和视觉—语言两个变体中观察到同一模式。」
- **前置条件**：
  - **依赖**：GeneralPoints 算术思考卡牌游戏（Chu 等人提出）；**Llama-3.2-Vision-11B** 基座；**带价值网络的 PPO** 实现（原书明确「RL 部分采用带价值网络的 PPO 算法」）。
  - **算力**：原书只规定「在相同计算预算下分别扩展 SFT 与 RL 训练」，未给出绝对值〔推测〕。
  - **数据**：**单一规则（J/Q/K=10）**的算术卡牌数据；训练用黑色花色（♠♣），测试用红色花色（♥♦）。
- **设计（控制变量）**：这是全章控制最严的一组对照——「相同任务、相同基础模型、相同计算预算，唯一的变量是训练方法」。实验分两个变体：**纯文本 GP-L** 与**图像 GP-VL**。**规则变体**：「训练时 J/Q/K 都计为 10，测试时分别计为 11/12/13，确保测试集出现训练未见的数字组合（含 11、12、13 的运算），严格评估泛化能力。」**视觉变体**：「训练用黑色花色（♠♣），测试用红色花色（♥♦），评估视觉外观变化下的鲁棒性。」
- **操作步骤**：
  1. 选定基座 Llama-3.2-Vision-11B，先做 **SFT 初始化**，使其具备基本指令遵循能力。
  2. 构造任务：使用四张卡牌上的数字，通过加减乘除运算、每个数字恰好用一次，凑出目标数字 24（类「24 点」）；训练全部使用 J/Q/K=10 的规则。
  3. 在相同计算预算下分别扩展 SFT 与 RL 训练（RL 用带价值网络的 PPO）。
  4. 构造 ID（分布内）与 OOD（分布外）测试集，覆盖规则 OOD 与视觉 OOD 两个维度。
  5. 在 GP-L 与 GP-VL 上分别测 ID/OOD 准确率。
  6. 追踪底层视觉识别准确率，与整体性能做相关性分析。
  7. 补做「无 SFT 冷启动的端到端 RL」对照，确认它失败在何处。
  8. 改变测试期验证迭代次数（1 次 vs 10 次），观察泛化测量值的变化。
- **关键代码或配置**：

  ```text
  基座：Llama-3.2-Vision-11B
  流程：SFT 初始化 → 相同预算下分别扩展 SFT / RL（带价值网络的 PPO）

  测试规则：J/Q/K 分别计为 11/12/13；花色改用红色（♥♦）
  ```

  - **测试期计算量的影响**：「在这个实验中，验证迭代次数越多，测得的泛化越好：10 次 +5.99% vs 1 次 +0.48%」。

- **常见陷阱**：
  - 把本实验读成「SFT 必然只能记忆，或 RL 必然学会通用算法」。原书对这条解释加了限定：「这解释了本实验中的“记忆”与“泛化”对照，但不是说 SFT 必然只能记忆，或 RL 必然学会通用算法。」
  - 把「RL 需要 SFT 初始化」当成普适规律。原书划定了条件：「在本实验的设定下（Llama-3.2-Vision-11B 这个量级的基础模型，加上严格的结构化输出要求），RL 需要先用 SFT 初始化：未经 SFT 直接做端到端 RL 完全失败，因为基础模型无法产生结构化输出，奖励根本无法计算。注意这是特定设定下的结论而非普适规律：足够强的基础模型可以跳过 SFT 直接 RL 成功（见前文对 DeepSeek-R1-Zero 的讨论）。」
  - 只测一次就报告泛化幅度——本实验自己给出反例：10 次验证 +5.99% vs 1 次 +0.48%。
- **关键结论**：
  - 「SFT 稳定格式，RL 在此基础上探索策略，两者形成互补。」
  - 本章小结的定调：「“SFT 记忆、RL 泛化”概括的是本章受控实验中观察到的倾向，并不是不受数据、模型、奖励与环境影响的普遍规律。」

## 实验 8-12 ★★★：V-IRL-VL——多轮视觉导航

- **原书位置**：§「多轮任务的核心挑战」
- **目的**：验证多轮任务中「策略需要学会根据当前观测重新规划，而不是复现训练轨迹」；并观察**逐步反馈**能否缓解长时序信用分配。
- **前置条件**：
  - **依赖**：V-IRL 真实城市街景环境；**带价值网络的 PPO**；支持视觉—语言输入的策略模型。
  - **算力**：原书未给出〔推测〕；多轮视觉导航的 rollout 成本高于单轮文本任务。
  - **数据**：训练使用**纽约路线**；测试迁移到**不同城市**，并同时改变方向表达与视觉外观。
- **设计（控制变量）**：同一条 PPO 配方下，把分布偏移拆成两类——**规则偏移**（方向表达改变）与**视觉偏移**（视觉外观改变），分别检查 SFT 与 RL 的表现，并与实验 8-11 的单轮结论对照。原书对其定位是：「RL 在规则和视觉 OOD 上都明显优于 SFT，说明在多轮任务中，策略需要学会根据当前观测重新规划，而不是复现训练轨迹。」
- **操作步骤**：
  1. 准备 V-IRL 真实城市街景环境与纽约训练路线。
  2. 用带价值网络的 PPO 训练导航策略（多轮交互，每轮含观察、动作与反馈）。
  3. 构造两类测试集：不同城市的路线（规则/方向表达偏移）与改变视觉外观的同一环境（视觉偏移）。
  4. 对比 SFT 与 RL 在两类 OOD 上的表现。
  5. 检查**逐步反馈**是否缓解了长时序信用分配——即中间步骤的反馈能否改善早期决策。
- **关键代码或配置**：

  ```text
  环境：V-IRL 真实城市街景（多轮连续导航）
  算法：带价值网络的 PPO
  训练分布：纽约路线
  测试偏移：① 不同城市 + 方向表达改变  ② 视觉外观改变
  观测：规则 OOD / 视觉 OOD 上 SFT 与 RL 的差距；逐步反馈对信用分配的作用
  ```

  - 单轮与多轮的对照、以及多轮中的信用分配问题，另见原书图8-14 与图8-15。

- **预期结果与判读方法**：
  - **预期结果**：RL 在规则与视觉 OOD 上都明显优于 SFT；逐步反馈能缓解长时序信用分配。
  - **判读要点**：看**两类 OOD 的方向是否一致**。若只在视觉 OOD 上占优而在规则 OOD 上持平，说明收益来自感知鲁棒性而非重规划能力——实验 8-11 已示范了如何用底层识别准确率把这两者分开。
- **常见陷阱**：
  - 把「RL 在 OOD 上更好」直接外推到所有多轮任务。原书在实验 8-11 与本章小结两处都强调这只是受控实验中的倾向。
  - 忽略「测试城市 ≠ 训练城市」这一硬约束：若测试仍用纽约路线，实验测的就只是记忆而非迁移。
  - 把逐步反馈当作免费收益——过程信号的代价见实验 8-16：它会引入路径塑形，且只在「部分进展可达」时才有效。
- **关键结论**：
  - 「实验使用带价值网络的 PPO，并观察到逐步反馈能缓解长时序信用分配。」
  - 多轮场景的判据：「在多轮任务中，策略需要学会根据当前观测重新规划，而不是复现训练轨迹。」这与本章「信用分配」一节的框架一致——原书在讨论多轮复杂度时指出，「这里讨论的多轮交互，正是第一章和第四章描述的 ReAct 循环——每一轮就是一次**思考 → 行动 → 观察**的迭代」。

## 实验 8-13 ★★★：SimpleVLA-RL——结果奖励下的开放探索 `[扩展实验]`

- **原书位置**：§「多轮任务的核心挑战」
- **目的**：验证**纯结果奖励**在「最优路径未知」时反而能保留更大的探索空间，并展示机器人操作任务中 RL 能从稀疏成败信号里发现演示中不存在的动作。
- **前置条件**：
  - **依赖**：LIBERO 机器人任务环境；一条演示轨迹用于 SFT 冷启动；支持 GRPO 的训练框架（原书在本章案例总表中把 SimpleVLA-RL 归入 GRPO 分支）。

## 实验 8-16 ★★★：RLVP——奖励结果、惩罚路径

- **原书位置**：§「结果正确还不够：路径约束与 RLVP」
- **目的**：验证在纯结果奖励之外加入**路径信号**能否在不牺牲成功率的前提下压掉违规行为，并量出「可达的部分奖励」对收敛速度的贡献。原书写明了机制主张：「它不改变 PPO/GRPO，只改变每一步看到的奖励。」
- **前置条件**：
  - **依赖**：GRPO 实现；一套能逐动作判定合规性的**确定性规则**（用于计算 $\Phi$）；任务级结果验证器（用于计算 $O$）。
  - **算力**：原书未给出〔推测〕；在 GRPO 基线上增量很小，因为「不改变 PPO/GRPO，只改变每一步看到的奖励」。
  - **数据**：TerminalBench 与 miniF2F；软件修复场景用于检验「进展信号不可达」时的表现。
- **设计（控制变量）**：同一 GRPO 配方下，**变量是奖励构成**——对照组为纯结果奖励，实验组为「结果奖励 $O$ + 路径信号 $\Phi$」，总奖励写成 $R=O+\beta\Phi$，「两路归一化后再合并，避免路径信号淹没主目标」。
- **操作步骤**：
  1. 定义结果验证器 `verify_final_state(trajectory)`——原书强调它取的是**结果而非自我报告**。
  2. 为每个动作实现确定性路径信号 `deterministic_path_signal(step)`：对可验证的违规动作扣分，对可验证的合规动作或可达子目标给少量部分奖励。
  3. 按两路归一化后合并：`reward = normalize(outcome) + beta * normalize(path_signal)`。
  4. 在 TerminalBench 上对比纯结果奖励与 RLVP 的**违规次数**与**成功率**。
  5. 在 miniF2F 上测量「达到 0.9 成功率所需迭代次数」。
  6. 构造「所有 rollout 都无法通过任何测试」的软件修复场景，验证进展信号不可达时的收益。
  7. 做可达性前置检查：先用少量 rollout 确认路径信号能否在组内产生差异。
- **关键代码或配置**（原书给出的实现骨架，逐字照录）：

  ```python
  outcome = verify_final_state(trajectory)              # result, not self-report
  path_signal = 0
  for step in trajectory:
      path_signal += deterministic_path_signal(step)    # penalty or reachable progress
  reward = normalize(outcome) + beta * normalize(path_signal)
  ```

  - 原书同时给出边界声明：「路径信号中的允许动作、可达子目标、隐藏测试和证据记录依赖具体环境；正文只说明“结果奖励”和“路径约束”如何合并，避免把某个环境的规则误当成通用算法。」

- **预期结果与判读方法**（原书实测数字，逐条照录）：
  - **TerminalBench**：违规次数由 **3.71 降至 0.66**，而成功率**基本持平**；
  - **miniF2F**：可达的部分奖励把达到 **0.9 成功率所需迭代从 7.0 降至 4.4**；
  - **软件修复**：「若所有 rollout 都无法通过任何测试，进展信号不可达，加入它不会带来收益。」
  - **判读要点**：三个数字要分三处读——违规次数是**安全指标**（降了才对），成功率是**不退化约束**（持平才可接受，掉分说明 $\beta$ 过大），迭代数是**效率指标**。原书由此提炼出本实验最重要的一句话：「这个实验提醒我们：**先测信号可达性，再决定是否增加奖励维度。**」
- **常见陷阱**：
  - 把 RLVP 当成万能合规层。原书划了两条边界：它「针对的是可机器判定的、与最终成败无关的**结果中性约束**；它不能替代对语义意图、交付完整性和早停行为的独立检查。」
  - 以为奖励越密越好。原书直接反驳：「RLVP 的关键不是“奖励越密越好”，而是能否恢复组内差异。」并给出机制解释：「纯结果奖励在全败组和全胜组都会产生零方差、没有梯度；违规动作通常容易检测，惩罚几乎总能恢复差异；进展奖励只有在部分进展可达时才有效。」
  - 惩罚「不够努力」这类模糊对象。四条设计纪律是：「只惩罚具体动作，不惩罚“不够努力”；结果奖励始终保留，避免模型学会什么都不做；每个惩罚最好配一条可达的合规路径；规则必须确定、难以钻空子。」
  - 在基础策略根本不会采样合规动作时就上惩罚——「应先用少量示范把这条路径“种”出来，待合规行为稳定后再逐步减弱路径塑形。」
  - 把代理环境的数字外推到线上：「这些数字来自可控的代理环境，不能直接外推为线上 Agent 也会获得同等提升；更稳妥的结论是机制性的：只要路径信号能在同一组 rollout 中区分行为，且规则不易被策略钻空子，它就能补上终点奖励看不见的那部分信息。」
- **关键结论**：
  - 「**奖励结果，惩罚路径**」，对应真实环境的**非对称验证器**特性：「检测“做了一个坏动作”便宜而可靠，证明“这一步确实朝着目标取得了有意义的进展”却很难。」
  - 惩罚与进展奖励的不对称：「惩罚是通常可达的那一半，进展奖励是受可达性门控的那一半。」
  - 部署层面的补充要求：「对于真实部署，还需要把隐藏验证、轨迹监控和外部终止条件一起纳入 Harness。」
- 〔精读批注〕本实验给出了奖励设计里最容易被忽略的一道**前置检查**——组内差异可达性。它与 GRPO 的机制直接咬合：16 条 rollout 全败或全胜时相对优势消失（本章 RL 算法一节的第三步），RLVP 的路径信号正是「解决如何在这些组里恢复有意义的差异」。做工程落地时建议把它做成一道门禁：**加任何新奖励维度之前，先跑 32 条 rollout 看组内方差**；方差为零的新维度只会增加被钻空子的面积。

  7. **双集验证**：用 boundary 12 条检查「任务未完成时，模型是否选择继续验证而非宣称完成」；用 retention 8 条检查「任务确实已完成时，模型应正常宣称完成」。

## 实验 8-18 ★★：作用域敏感的中文弯引号 SFT

- **原书位置**：§「案例 2：中文引号」
- **目的**：原书写明：「验证 LoRA SFT 能否让模型在混合中文、英文、Markdown、代码和 JSON 的文档中，准确执行“该改的引号改弯、受保护的引号不动”，并在未见过的上下文组合上保持这一边界。」
- **前置条件**：
  - **依赖**：**`Qwen/Qwen3-8B`** 基座；**bf16 LoRA** 训练流程；一份 `SKILL.md` 作用域规则；生产侧的解析器与语法检查。
  - **算力**：8B LoRA，**训练 2 个 epoch（256 次更新）**；原书未给出卡型〔推测〕。
  - **数据**：按 **16 类片段、10 种文章体裁、9 种编程语言**渲染 **1024 条训练样本、256 条留出样本和 256 条边界样本**；样本成对保存原文与目标文本。
- **设计（控制变量）**：把「规则」外置成一份可复用的 `SKILL.md`——原书写明它「的作用域规则同时作为生成标签、质量门禁和回归规范；模型只负责选择作用域和生成最小编辑，生产侧的解析器与语法检查不被移除」。这是「规则 + 模型」分工的显式设计：模型不做规则判断，只做作用域选择与最小编辑生成。
- **操作步骤**：
  1. 写出 `SKILL.md`：把引号使用规则表述为作用域敏感的最小编辑规则——「中文自然语言中的引用可以转换为 `“”`，嵌套引用按中文标点规则处理；英文原文、可执行代码、JSON/schema、路径、标识符和 Markdown 反引号中的内容必须原样保留；无法判断作用域时应保留原文。」
  2. 用该规则渲染数据：16 类片段 × 10 种体裁 × 9 种语言 → 1024 条训练样本 + 256 条留出样本 + 256 条边界样本。
  3. 样本成对保存原文与目标文本；正例覆盖中文段落、嵌套引用以及代码注释中的中文自然语言；反例覆盖英文原文、字符串/字符字面量、JSON、路径、行内代码和整段代码。
  4. 以 `Qwen/Qwen3-8B` 为基座做 bf16 LoRA 训练，2 个 epoch（256 次更新）。
  5. 在留出集与边界集上评估：既要「该改的改弯」，也要「受保护的不动」。
  6. 保留生产侧解析器与语法检查，作为模型输出之后的第二道闸。
- **关键代码或配置**：

  ```text
  基座：Qwen/Qwen3-8B
  训练：bf16 LoRA，2 个 epoch（256 次更新）
  规则载体：SKILL.md（作用域规则 = 生成标签 + 质量门禁 + 回归规范）
  数据：16 类片段 × 10 种文章体裁 × 9 种编程语言
        1024 训练 / 256 留出 / 256 边界；成对保存原文与目标文本
  正例：中文段落、嵌套引用、中文代码注释中的自然语言
  反例：英文原文、字符串字面量、JSON、路径、行内代码、代码块、嵌套结构
  保留：生产侧解析器与语法检查
  ```

- **预期结果与判读方法**：
  - **预期结果**：模型在混合文档中准确执行「该改的引号改弯、受保护的引号不动」，并在**未见过的上下文组合**上保持这一边界。
  - **判读要点**：评估必须**双向**计数——漏改（该改没改）与误改（该留没留）是两类不同的错误，只报准确率会掩盖它们的不对称代价。本实验的命名也提示了判读重点在**作用域**而不是**字符**：正确行为是「先判断作用域，再做最小编辑」，不是「看到直引号就替换」。
- **常见陷阱**：
  - 把这条需求当成可枚举的字符串替换规则——原书开头就指出：「这句话描述了期望，却没有给出可以直接训练的规则：同一个引号，在中文自然语言、英文原文、Markdown 行内代码、代码块、代码注释、JSON 或路径中承担的角色完全不同。」
  - 拿掉生产侧的解析器与语法检查，把全部正确性押在模型上。
  - 训练数据体裁/语言覆盖不足，导致模型在未见组合上失去边界。本实验用 16×10×9 的渲染维度正是为了对抗这一点。
  - 忘记「无法判断作用域时应保留原文」这条兜底规则。
- **关键结论**：
  - 「正确的修复是**作用域敏感的最小编辑**」；「这样教给模型的是 “先判断作用域，再做最小编辑”，而不是 “看到直引号就替换”。」
  - 本章新增的两个问题案例实验共享同一套底座协议：「二者共享第七章的失败归因和训练/评估隔离协议，但采用不同的评分标准：前者测“该改才改、该留则留”，后者测“必须逐字复制”。」
- 〔精读批注〕本实验最值得带走的是**规则的存放位置**：`SKILL.md` 同时充当生成标签、质量门禁和回归规范——一份规则三处复用。这意味着规则改动会同时改数据分布与评估口径，版本管理必须跟上。另一个工程含义是分工边界：把「判断作用域」这种需要语义理解的部分交给模型，把「语法是否合法」这种确定性的部分留给解析器，恰好对应本章「能力能否被外部符号充分表达」这条选择依据。

## 实验 8-19 ★★：特殊字符串的精确复制 SFT

- **原书位置**：§「案例 3：编辑文件经常失败」
- **目的**：原书写明：「在已确认差异来自模型抄写错误的前提下，测试 LoRA SFT 能否提升模型对随机字符串的精确抄写，并用独立 tokenizer 审计排除词元化造成的假象。」
- **前置条件**：
  - **依赖**：**`Qwen/Qwen3-8B`** 基座；**bf16 LoRA** 训练流程；独立 tokenizer 审计工具。
  - **算力**：8B LoRA，**2 个 epoch**；原书未给出卡型〔推测〕。
  - **数据**：三类可验证的复制任务；样本特意包含真实编辑最容易损坏的空格、真实换行、反斜杠、Unicode 等；另用留出与边界共 **512 条探针**比较三个开源 tokenizer。
- **设计（控制变量）**：监督范围被刻意收窄——「训练脚本只对目标字符串或 `old_string` JSON 字段提供逐 token 监督。」样本形态有三种：「直接逐字复述；在相似且等长的多个字符串中选择完全相同的目标；以及把指定字符串完整抄写到 `old_string` 的工具 JSON 参数。」
- **操作步骤**：
  1. **先做归因，再决定是否训练**：沿链路逐层对比——「文件原始字节 → 工具返回 → Harness 序列化 → 模型上下文 → 模型 token 输出 → 解码字符串 → JSON/tool-call 解析 → 工具匹配。」
  2. 按归因规则定位责任方：「若文件读取或工具返回已经改变字节，归因给工具；若序列化、转义或提示词拼装改变了内容，归因给 Harness；如果 tokenizer encode 后再 decode 发生变化，归因给 tokenizer。只有模型收到的上下文与原始字符串完全一致，而**模型输出是链路上首个出现差异的位置**，才能把它标为模型的精确复制能力问题，作为后训练候选。」
  3. 构造三类复制任务的数据，特意保留空格、真实换行、反斜杠、Unicode 等易损字符。
  4. 以 `Qwen/Qwen3-8B` 为基座做 bf16 LoRA，2 个 epoch，**只对目标字符串或 `old_string` JSON 字段提供逐 token 监督**。
  5. 在留出集与独立边界集上测 byte-exact accuracy。
  6. 用独立 tokenizer 审计：在留出与边界共 512 条探针上比较三个开源 tokenizer 的无损 round-trip 率。
- **关键代码或配置**：

  ```text
  基座：Qwen/Qwen3-8B
  训练：bf16 LoRA，2 个 epoch
  监督范围：只对目标字符串 / old_string JSON 字段提供逐 token 监督
  三类任务：① 直接逐字复述 ② 在相似等长候选中选出完全相同者 ③ 抄进 old_string 工具 JSON 参数
  易损字符：空格、真实换行、反斜杠、Unicode
  审计：留出 + 边界共 512 条探针，比较三个开源 tokenizer 的无损 round-trip
  ```

- **预期结果与判读方法**（原书给出的结果，逐字照录）：
  - 「模型留出集 byte-exact accuracy 从基座的 **37.5% 提升到 78.9%**，独立边界集为 **80.1%**；平均首次字节分歧位置分别为 **54.0 和 54.2**。」
  - 「另用留出与边界共 512 条探针比较三个开源 tokenizer，Qwen3 与 Qwen2.5 的无损 round-trip 均为 **80.1%**。因此 **80.1% 同时反映了模型复制和 tokenizer 上限**。」
  - **判读要点**：看到「模型 80.1% = tokenizer 上限 80.1%」这个巧合时，正确结论**不是**「模型已达上限、无需再训练」，而是**上限这一项必须被单独审计**——如果 tokenizer 的无损 round-trip 只有 80.1%，那么剩下约 20% 的失败在模型侧根本不可能被 SFT 修好。这正是原书要求「用独立 tokenizer 审计排除词元化造成的假象」的原因。
- **常见陷阱**：
  - 跳过归因直接上训练。原书把归因规则写得很死：只有「模型输出是链路上首个出现差异的位置」时才把它标为后训练候选；工具、Harness、tokenizer 三个环节的问题都不该用 SFT 解决。
  - 把 byte-exact 失败一律归咎于模型——必须先用独立 tokenizer 探针把词元化造成的假象排除。
  - 忽略「平均首次字节分歧位置」（54.0 / 54.2）这一指标：它说明分歧往往发生在长字符串的后半段，属于**长程保真**问题，而不是「不会复制」。
  - 只训不测边界：本实验专门保留了一个独立边界集（80.1%），与留出集（78.9%）分开报告。
- **关键结论**：
  - 「这样教给模型的是」逐 token 的保真度；与实验 8-18 的分工是：「前者测“该改才改、该留则留”，后者测“必须逐字复制”。」
  - 两个案例共享底座协议：「二者共享第七章的失败归因和训练/评估隔离协议」。
  - 编辑工具失败的结构性原因：「编辑工具通常按精确字符串匹配，哪怕只差一个空格、换行、反斜杠、Unicode 组合字符或低频 token，都会返回失败。」
- 〔精读批注〕本实验给出了一条**归因优先于训练**的范式：链路共八层，训练只负责最后一层。它也顺手暴露了一个常被忽视的上限来源——tokenizer。把 80.1% 同时读作「模型分数」和「词表容量」是本章最漂亮的一处诚实计算：报任何复制类指标时，都应该同时报一次 tokenizer 的无损 round-trip，否则你无法解释天花板的来源。
